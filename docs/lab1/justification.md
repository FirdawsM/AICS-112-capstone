# Why high-impact containment stays human-approved

I keep isolate_endpoint and disable_identity behind a named human decision because a wrong call stops real work. In a microfinance business, an isolated finance laptop can block payments, and a disabled privileged account can lock out the responders. The risk score comes from a small synthetic dataset, so it can be wrong. An AI summary can hallucinate, and event text can carry a prompt injection. An analyst can check what the pipeline cannot see, such as travel, a change window or a batch job. Low-impact steps like creating a case run automatically because they are easy to undo. High-impact steps wait for approval, stay dry run, and every decision goes into a hash-chained audit log. Speed matters, but an unexplained containment costs more than a ten-minute wait. The approver also owns the decision, which gives the audit trail a person to ask during a review.
